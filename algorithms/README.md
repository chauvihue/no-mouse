# Algorithms

Pure TypeScript signal-processing code for the wrist IMU mouse (MPU-6050 on an ESP32). No DOM, no imports from the app, so it can be ported to the device firmware. The app lives in `../Simulation`, which imports from here with relative paths, and `../Simulation/README.md` covers how the app uses these pieces.

```
algorithms/
  README.md                this file
  package.json             {"type":"module"} so the .ts files load as ES modules when run by node
  config.ts                every tunable parameter in one PipelineConfig object, step toggles, app preset
  pipeline.ts              Pipeline.step(sample) → cursor, state, tap events (the per-sample orchestration)
  shared/math.ts           quaternions, rotations, G and DEG constants
  fusion/madgwick.ts       Madgwick orientation filter (gyro + accel)
  fusion/gravity.ts        accel-only gravity tracking: complementary filter and Kalman filter
  motion/stroke.ts         stroke tracker: speed-up → slow-down → halt, velocity exactly 0 between strokes
  taps/classifier.ts       tap features and the index/pinky classifier (logistic regression or nearest centroid)
  clicks/detector.ts       streaming left/right click detector (high-pass, thresholds, causal decision)
  clicks/model.ts          trained logistic model for the click detector (generated by train-clicks; do not edit)
  calibration/accel-six-face.ts   six-face accelerometer calibration maths (bias, scale, apply)
```

**Pipeline and config** (`pipeline.ts`, `config.ts`). `Pipeline.step(sample)` runs the steps in order, each with a toggle in `PipelineConfig` (`enableCalibration`, `enableFusion`, `enableGravityRemoval`, `enableZupt`, `enableRestDetect`, `enableSlideDetect`, `enableVelocityDecay`, `enableDeadzone`, `enableSpeedCurve`, `enableClickFreeze`, `enableTaps`). Inputs are `ImuSample` values (`t` in seconds, accel in g, gyro in °/s). Outputs are a `StepOutput` with the cursor, phase and any `TapEvent`. `APP_PIPELINE_CONFIG` is the preset the app starts with, and `DEFAULT_PIPELINE_CONFIG` is the baseline. `accelBias` and `accelScale` are the saved accelerometer calibration (applied as (raw − bias) · scale). `fusionMode` (`madgwick`, `accel-kalman`, `accel-complementary`, `gyro-only`, `static`) selects orientation. `motionModel` (`integrate`, `stroke`, `segment`) selects how acceleration becomes motion. `classifier` (`logistic`, `centroid`) selects the tap model.

**Start-up calibration** (inside `pipeline.ts`, step 1). About 1 s of stillness gives the gyro bias and the gravity vector, which initialise orientation. While still, the gyro bias is refined slowly (`biasTracking`, `biasTrackingTauS`). Left inside `pipeline.ts`, not extracted.

**Orientation** (`fusion/`). Madgwick fuses gyro and accel and corrects tilt from the accelerometer only while the hand is still (`betaStill`, `betaMoving`, `accelGateG`). The accel-only modes instead track gravity in `GravityTracker`: complementary low-pass (`compTauS`) or Kalman (`kalmanTiltRate`, `kalmanNoiseG`, `kalmanSpreadFloorG`, `kalmanMotionK`). Tested by `npm run verify`, `npm run bench:pan` and `npm run bench:real`.

**Stillness and motion.** `pipeline.ts` also holds the stillness test (zero-velocity reset, `stillWindowMs`, `stillAccelG`), the tilt-proof rest test (step 4b, re-levels Madgwick), and the desk-vibration sliding detector (step 4c). Strokes are driven by `motion/stroke.ts`: `strokeLpHz`, `strokeRelFrac` and `strokeLeakGain` tune it, and `segment*` settings in `config.ts` configure the optional rest-to-rest correction. Tested by `npm run verify` (section 6), `npm run bench:moves` and `npm run bench:real`.

**Taps** (`taps/classifier.ts`, used by `pipeline.ts` and the harness). A 45 ms window around each high-passed impact gives the features in `FEATURE_NAMES`. `TapClassifier` (logistic or nearest centroid) labels the tap `index` or `pinky`. Tested by `npm run verify` (section 4).

**Click detector** (`clicks/detector.ts`, `clicks/model.ts`). A streaming left/right detector used by the Click tester. It high-passes accel and gyro, sets a noise floor from the still hand, detects taps above that floor, waits `DECISION_DELAY_S` (100 ms) so the decision is causal, then scores the five most separable features with `CLICK_MODEL` for P(left). `npm run train:clicks` refits the model from recorded takes and rewrites `clicks/model.ts`. `npm run analyze:clicks` reports detection and cross-take accuracy.

**Six-face accelerometer calibration** (`calibration/accel-six-face.ts`). Resting the board on each of six faces gives bias = (up + down) / 2 and scale = 2 / (up − down) per axis. `accelFaceFromMean` names the face a still reading rests on. `accelCalFromFaces` returns bias, scale and any problems (bias over 150 mg, scale outside 90–110 %). `applyAccelCorrection` applies the result to one reading. The app (`Simulation/src/ui/main.ts`) runs the guided flow, still detection and localStorage. The pipeline keeps its own inline copy of the correction (`pipeline.ts`, the accel step).

**Shared helpers** (`shared/math.ts`). Quaternion multiply, rotate to world or sensor frame, Euler and gravity to quaternion, yaw and roll/pitch. Used by the pipeline, fusion and the simulator in `Simulation/src/sim/imu.ts`.

**Tests and benchmarks that use these files** (run from `Simulation/`):
- `npm run verify` (`scripts/verify.ts`): headless checks of the physics and the pipeline (17 checks).
- `npm run bench:pan` (`scripts/bench-pan.ts`): scores the panning protocol recordings.
- `npm run bench:moves` (`scripts/bench-moves.ts`): scores the motion pipeline move by move.
- `npm run bench:real` (`scripts/bench-real.ts`): scores the motion pipeline on real recordings.
- `npm run analyze:clicks` and `npm run train:clicks` (`scripts/analyze-clicks.ts`, `scripts/train-clicks.ts`): click detector analysis and model training.
